## 怎么读

- **第一次上手 → 从第 1 篇开始**，按它的步骤走。**第 1 篇不含任何 NB-IoT 内容** ——
  它是地基：跑通 = 你手上有了一个「能改代码、能烧进去、能看日志」的环境，
  后面所有联网、外设的实验都建在它上面。
- **只想知道"这块板子能不能上网"→ 直接看第 2 篇 §1**（一分钟判据，三条指令）。
- **想把数据真的发出去、长期挂着 → 看第 3 篇**。它把「人在 PC 上敲 AT」变成「固件自己干」：
  上电 → 注网 → 建 socket → 每 30 秒一条。里面有三样别处看不到的东西：
  **公网裸端口为什么要挡一层 token**、**厂家的 `BC28.c` 哪三处不能照抄**、
  以及**一篇"我预测错了"的对照实验记录**。
- **想点亮墨水屏 / 想知道这块屏能拿来干什么 → 看第 4 篇**。
  它给的不只是驱动：还有**实测刷新耗时**，以及一笔很实在的
  **「刷新寿命账」**（100 万次配额）—— 那一节决定「墨水屏适不适合显示时间」这类问题的答案。
- **各篇都照实说**：凡是我**没验证过**的东西，一律单列一节标出来，
  不拿"应该可以"糊弄你；没打通的也照实写。

## 一句话结论

- **第 1 篇**：把「改代码 → 烧进去 → 看日志」这个循环转起来。
- **第 2 篇**：让 BC28 **联上网**，并且用 PC **真的**跟模块收发 TCP 数据
  （实测收回了对方服务器的完整 HTTP 响应）。
- **第 3 篇**：**固件自己把数据发到自己的服务器** —— 上电不用人管。
  境外那台服务器上**同一个 TCP 连接连续挂了 63 分钟、发出 110 条、服务端一条不落**。
  三件副产品：**域名解析用模块自带的 `AT+QDNS`**（家宽动态 IP 不用重烧固件）、
  **一篇否定自己预测的 A/B 实验**、以及一条方法论 ——
  **串口报的丢包数是不可信的，判丢包只看服务端日志的序号连续性**。
- **第 4 篇**：把墨水屏**点亮**（250×122 全刷实测 **2521 ms**，效果正确、无残影），
  修掉厂家驱动两处真 bug，并算清**这块屏能刷多少次** ——
  「**1 秒一次 11 天就报废、1 分钟一次能用 2 年**」，所以它不适合做秒级时钟。
