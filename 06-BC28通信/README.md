# 自己写的 BC28 socket 驱动 + 服务端 sink

**这一份干的事**：让固件**自己**完成「注网 → 建 socket → 每 30 秒把一行数据发到自己的服务器」。
上电之后**不用 PC、不用人看着**，这正是系列主线从第 2 篇（人手敲 AT）跨到第 3 篇的那一步。

配第 3 篇正文看：**[第3篇-把数据发到自己的服务器.md](../第3篇-把数据发到自己的服务器.md)**。

> **它不用厂家的 `BC28.c`** —— 驱动整个自己写。厂家那份 283 行的问题在下面 §五 逐条列，
> 它**不参与编译**，只在文章里做对照。跟第 4 篇不搬 `smp.c` 是同一个做法。

## 二、三个开关（这篇所有的实验都靠它们）

| 宏 | 在哪 | 值 | 作用 |
|---|---|---|---|
| `MODE_LONG` | `main.c` | **`1`（本目录默认，推荐）** / `0` | `1` = 建一次连接一直用；`0` = 每轮「建连→发→收→关」 |
| `BC28_SKIP_NSOCO_URC` | `main.c` 顶部，**必须在 `#include "bc28.h"` 之前** | `0`（默认）/ `1` | `0` = 等到 `+NSOCO: <n>` URC 才算连上；`1` = **复现厂家写法**，收到 `OK` 就发 |
| `REPORT_MS` | `main.c` | `30000UL` | 上报间隔 |

> ⚠️ `BC28_SKIP_NSOCO_URC` **必须定义在 `#include "bc28.h"` 之前** ——
> `bc28.h` 里那一段是 `#ifndef` 保护的，先定义才能盖住它的默认值。

第 3 篇三个实验各自用的取值：

| 实验 | `MODE_LONG` | `BC28_SKIP_NSOCO_URC` | 拿到什么 |
|---|---|---|---|
| 实验一 长连接 | `1` | `0` | 境外单连接 **63 分钟 / 110 条 / 0 丢**；家里 14 次重连、**`+NSOCLI` 12 次** |
| 实验二 A/B 对照 | `1` | `1` ↔ `0` | **没做出定论**（详见正文 §6，结论跟我预测的相反） |
| 实验三 短连接 | `0` | `0` | 建连耗时 **min 3003 / max 20227 / 平均 5852 ms** |

## 四、驱动长什么样

**三层**，分清楚很重要（正文 §8 那条"串口 `lost` 不可信"就是被这个分层坑的）：

```
┌─ 应用层  main.c ──────────────────────────────────┐
│  link_up()     建连 + 交 token                     │
│  report_once() 组一行数据、发出去、读回执           │
│  wait_reply()  ← ⚠ "收不到就再试 3 轮" 的**策略**在这 │
└───────────────────┬───────────────────────────────┘
┌─ 驱动层  bc28.c ──┴───────────────────────────────┐
│  BC28_Recv()   一 次 AT+NSORF，收到就返回           │
│  at_cmd()      发一条 AT（先清缓冲）再等            │
│  wait_for()    在收缓冲里等一个固定串               │
│  read_field()  读到下一个换行为止                   │
└───────────────────┬───────────────────────────────┘
┌─ 硬件层 ──────────┴───────────────────────────────┐
│  rx_pump()     把 USART2 收到的字节搬进线性缓冲      │
└───────────────────────────────────────────────────┘
```

**驱动里没有"丢包"这个概念** —— `BC28_Recv()` 只回答"这一枪有没有读到"。
`main.c` 那个 `lost` 计数器是应用层自己发明的。

接口一览（`bc28.h`）：

| 分类 | 函数 |
|---|---|
| 时基 / 空转 | `BC28_Init()`、`BC28_Idle(ms)`、`BC28_Millis()` |
| 模块 | `BC28_Probe()`（`AT`→`ATE0`→`ATI`）、`BC28_WaitNet(to)`、`BC28_GetRadio(&r)` |
| socket | `BC28_Resolve(host,ip,cap)`、`BC28_Open/Connect/Send/Recv/Close` |
| 诊断 | `BC28_SocketClosed()`、`BC28_RxOverflow()`、`BC28_NsocoDelayMs()`、`BC28_Why(rc)`、`BC28_DumpRx()` |

返回值：**`>= 0` 成功，`< 0` 错误码** —— `-1` 参数 / `-2` 超时 / `-3` 模块回 `ERROR` /
`-4` 没分到 socket / `-5` 回了 OK 但解析不出来。`BC28_Why(rc)` 翻成能直接打日志的短串。

**超时档位不是拍脑袋的**（每个都有出处）：

| 常量 | 值 | 依据 |
|---|---|---|
| `BC28_TO_AT` | 1000 ms | 普通 AT |
| `BC28_TO_LONG` | 2000 ms | 要翻一翻的指令 |
| `BC28_TO_STATS` | 5000 ms | `AT+NUESTATS` 是回得最慢的一条 |
| `BC28_TO_NSORF` | 5000 ms | 单次 `AT+NSORF` |
| `BC28_TO_URC` | 30000 ms | **`+NSOCO` URC 实测 3~20 秒**、**DNS 解析 2~3 秒** |
| `BC28_TO_NET` | 120000 ms | 冷启动注网要重新找小区 |

> **为什么 URC 给 30 秒而不是平均值**：建连耗时是**长尾**分布（实测 35 轮里，
> 绝大多数 3~8 秒，出过一次 20.2 秒）。按平均值（5.8 秒）给就会把那一次误判成失败。

## 五、为什么不用厂家的 `BC28.c`（三处，回原文核过）

厂家那份 `HARDWARE/BC28/BC28.c` 共 **283 行**、`BC28.h` **18 行**。

| # | 问题 | 原文 |
|---|---|---|
| 1 | **建连只等 `OK`，从不认 `+NSOCO` URC** | `BC28_ConTCP()` 的循环 `errcount>10; Delay(30);` ≈ **0.33 秒**就放弃；整个文件里 `+NSOCO` 只出现在一句注释和一句 `sprintf` 里，**没有一处是在等它** |
| 2 | **收数走 256 字节的 `buf_uart2`，满了静默回绕** | `usart.c`: `if(buf_uart2.index >= BUFLEN) buf_uart2.index = 0; else buf[buf_uart2.index++] = ch;` —— **不留任何溢出标记**，`strstr` 可能命中一条被截断/拼接过的"回显" |
| 3 | **socket 号按字符位置硬取** | `strx = strstr(buf,"STREAM,6,0,1"); socketnum = strx[14];` —— 回显多/少一个空格就取错，**而且取错后无任何检查** |

本驱动对应的做法：**等 `+NSOCO` URC**（并记录 `BC28_NsocoDelayMs()`）；
**自己的线性缓冲**（1024 字节，满了**不覆盖**、置 `rx_ovf` 标记、上层可查）；
**扫数字**取 socket 号，不依赖位置。

> **两条更正**（我原先记错过，这里按原文更正，别按印象引）：
>
> - "厂家每种状态循环 100 次 × 300ms = 30 秒" —— **那是 `BC28_Senddata()`**，
>   `BC28_ConTCP()` 是 `errcount>10` × `Delay(30)` ≈ **0.33 秒**，差 100 倍。
> - 厂家 `BC28_Senddata("13","7777772e637367736d2e636f6d")` 这个调用**是对的**：
>   `13` 是原始字节数，26 个 hex 字符解出来正好是 `www.csgsm.com`（13 字节）。**两点都对。**

## 六、这篇踩出来的坑（都在正文 §8 有对照表）

1. **`AT+QDNS` 是两段式响应。** `OK` 只是"受理了"（≤300 ms），
   `+QDNS:<ip>` 是**另发一条**（解析本身要 2~3 秒）。跟 `AT+NSOCO` 同一个形状。
   **第二层坑**：`wait_for()` 一命中期望串就返回、且**只消费到命中末尾**，
   所以命中 `+QDNS:` 时缓冲里只剩 IP 那半截，得自己接着 `read_field()` 读到换行。
2. **`+NSORF` 回显不带前缀。** 手册**表格标题**写 `+NSORF:<...>`，
   但**正文 Example 和真机都不带**（直接 `2,<ip>,<port>,<len>,<hex>,<remain>`）。
   按表格标题去 `strstr("+NSORF:")`，症状是"上行通了、服务端也回了，
   但固件永远说 no reply"—— 单看现象猜不到是差一个前缀。**以 Example 段为准，别信表格标题。**
3. **串口报的 `lost` 不可信。** 实测：家里那轮串口自报 `lost 11`，服务端实收 `#1`→`#69`
   **一条不少**；短连接那轮自报 `lost 16`，服务端**真丢 1 条**。
   判丢包只看两样：**服务端日志的序号连续性** + 报文里的 **`UP` 列**（板子自报 uptime）。
4. **大缓冲必须 `static`。** 本工程 `Stack_Size = 0x400`（**1 KB**），
   而 `BC28_Send()` 里那个十六进制命令缓冲最长 416 字节 ——
   放栈上会踩穿，现象是"发到某一条就死机"，**编译不报错、运行时才炸**。

## 七、服务端怎么部署

```sh
# ① 传上服务器
scp sink.py deploy_sink.sh root@<你的服务器>:/tmp/

# ② 在服务器上（要 root：写 /etc/systemd/system 和 ufw）
mkdir -p ~/nbiot-sink && mv /tmp/{sink.py,deploy_sink.sh} ~/nbiot-sink/
sh ~/nbiot-sink/deploy_sink.sh          # 会自己生成 token 并打印一次
```

脚本会做四件事：**生成 token 写进 `sink.env`(600)** → 装 systemd 服务 →
`ufw allow 9101/tcp`（**只放这一个**）→ 自检（`nc` 打一行，日志里应当出现 `AUTH` + `RX`）。

`DIRECTORY` 和 `SINK_PORT` 两个环境变量可以覆盖默认值，换台机器不用改脚本。

**口令换一下**：脚本会打印 `#define SINK_TOKEN "..."` 那一行，把它复制进 `main.c`。

**日志在哪 / 怎么读**：

```sh
grep -c ' RX ' logs/sink.log          # 一共收到多少条
grep ' AUTH '  logs/sink.log          # ★ 每条连接一条 —— AUTH 的次数就是对方重连了几次
grep ' REJECT ' logs/sink.log         # 谁扫过这个端口
python3 sink.py --stats               # 收了多少条 + 相邻间隔的 min/中位/max
```

**判断丢包（服务端视角）**：

```sh
grep ' RX  ' logs/sink.log | sed 's/.*#\([0-9]*\),.*/\1/' | sort -n | awk '
  NR==1 { prev=$1; first=$1; next }
  { if ($1 != prev+1) print "缺口: " prev " -> " $1; prev=$1 }
  END { print "首 " first ", 尾 " prev }'
```

> ⚠️ `sink.py` 的 `timeout = 600` 是"这一行 600 秒还没来就断开"。
> 它让日志里的 **`INFO` 滞后真实断开最多 600 秒**（连接静默死掉时尤其明显）。
> **判断"连接活了多久"要用 `AUTH` 到下一个 `AUTH` 的间隔，不要用 `INFO` 的时间戳。**
> 想让它更准，把这个数调小（90 秒左右）。

## 八、别被绊到的地方

| 现象 | 原因 |
|---|---|
| 串口一个字节都没有 | `printf` 走的是 **USART1**（PA9/PA10，CH340），不是模块那条 USART2 |
| `AT` 敲了几十次没回应 | 模块在 PSM 里睡着，第一个字符丢 —— 正常，`BC28_Probe()` 的重试就是为它写的 |
| 服务端 0 行日志，但字节确实到了 | **发出去的字符串没有行尾 `\r\n`**。`sink.py` 用 `readline()`，没换行它会一直等 |
| 服务端说收到了，串口说 `lost N` | **判据错，不是链路错**（见 §六.3） |
| 产物名还叫 `STM32L152-EVAL` | 厂家留下的名字，跟本板（STM32L151RC）对不上。**故意没改**，跟 04-AT透传 一致 |

## 九、发布前必须处理掉的

**不能进公开仓库**：`SINK_TOKEN` 真值、服务器真实 IP 和域名、家宽公网 IP、
模块的 **IMSI / IMEI / ICCID / 内网 IP / Cell ID / PCI**、`_bc28test.log` 这类带模块标识的日志。
