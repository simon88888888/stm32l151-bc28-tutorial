## 二、调传感器的顺序（**别跳步**）

**先调 DHT11，再联网。** 两件事互不相关，混在一起调会分不清是谁坏了。

```
① DHT11_SELFTEST = 1，PB8 上什么都不接，抓 25 秒串口
      → 应当 10 条 "FAIL (-2) no response"，且 start= 在 20000 上下
      → 这一步同时验了"起始脉冲发出来了"和"微秒尺子准"
② 按手册 §2 认针、插上模块，再抓 25 秒
      → 应当 10 组两行的成功读数
      → 看第二行的 hi0<= / hi1>= 有多少余量（手册 §6.2 有实测对照表）
③ DHT11_SELFTEST = 0，重烧，抓 90 秒
      → 报文尾部应当带上 ,T=
```

接线只有一句要记住：**模块的 `+` 要挨着板子的 `+`**。
两边丝印顺序**不一定一样**，认不准就先量电阻（手册 §2）。

## 三、服务端

### `sink.py` —— 第 3 篇那版的**升级版**

**在第 3 篇 `sink.py` 的基础上多落一份 SQLite**（纯文本 `sink.log` 照旧）：
`rx` 表一行 = 一条上报，`conn` 表一行 = 一次建连。这是看板能画历史曲线的前提。

原则是「**日志仍然是唯一真相**」—— DB 写失败只在 stderr 留一行，
**绝不影响收数、更不会断连接**。

```bash
SINK_TOKEN=<你自己定的串> python3 sink.py
```

环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `SINK_TOKEN` | **必填**，没设直接拒绝启动 | 公网裸端口必须有鉴权 |
| `SINK_PORT` | `9101` | |
| `SINK_LOGDIR` | `/opt/nbiot-sink/logs` | |
| `SINK_DB` | `/opt/nbiot-sink/data/history.db` | **本版新增** |

### `backfill.py` —— 把已有的 `sink.log` 回填进库

**幂等**：只插「早于库里最早那条」的记录，重复跑不会插重。
刚上线时跑一次，看板就有历史曲线，不用干等新数据。

```bash
python3 backfill.py
```

### `nbiot_dash.py` —— 看板页面

自包含的一个模块：自己的 CSS + JS（canvas 画曲线，**不引任何 CDN**），
数据走一个 JSON 接口。**只读**打开数据库：

```python
sqlite3.connect("file:%s?mode=ro" % DB, uri=True)
```

两个入口：`page()` 返回整页 HTML，`payload(h)` 返回 JSON（`h` = `1/6/24/168/all`）。

**挂进你自己的 web 应用时有一个必须注意的点**：

> **路由要注册在 catch-all 反代路由之前。** 门户通常有一个
> 「其余路径全部反代给上游」的兜底路由（形如 `/{path:path}`），
> 按注册顺序匹配的话，**兜底写在前，新页面就永远轮不到**。

而且**要用 `try` 包住 import** —— 看板崩了顶多这一页打不开，不能把整个门户带下水。

页面里有两个地方要按你的环境改：

- 顶部那个 `<a href="/apps">← 服务总览</a>` 回链 —— 指到你自己的门户根，或者删掉；
- 底部说明里提到的 `site.json` 路径（**经纬度是手工填的** —— 板子上没有 GPS，手册 §10.3）。

## 五、本篇踩的坑，一句话一条

1. **DHT11 模块的引脚顺序不一定是 `VCC/DATA/GND`** —— 量 `S` 对另外两脚谁有 4.7k 再插。
2. **`DHT11_Init()` 必须自己开 GPIOB 时钟** —— 那个时钟在**从没被调用过的** `uart3_init()` 里，不开就是静默失效。
3. **STM32L1 没有 32 位 `BSRR`**，只有 `BSRRL`（置位）/ `BSRRH`（复位）。
4. **边沿循环里别调函数** —— `GPIO_ReadInputDataBit()` 是函数，-O0 下 1~2µs，正好吃掉 20µs 余量。
5. **校验和通过 ≠ 数据有意义** —— 湿度恒 0 但校验和对，是它真在发 0。
6. **DHT11 温度整数部分的最高位是符号位** —— 按无符号打，-5°C 会变成 251°C。
7. **★ MCU 复位不会复位 BC28** —— 模块状态跨烧录、跨复位键一直留着，"换了固件也一样坏"。
8. **★ `AT` 能回 OK ≠ 模块是活的** —— socket 泄漏光时，`CSQ` / `RSRP` 完全正常，只有 `AT+NSOCR` 回 ERROR。
9. **★ 信号差能解释一切现象，所以它是最危险的答案** —— 一定要拿 AT 侧读数跟故障时间点对照。
10. **门户加页面，路由要注册在 catch-all 之前** —— 按注册顺序匹配，兜底写在前就永远轮不到。
