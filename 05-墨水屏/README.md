# 墨水屏最小驱动 + 综合测试页

**这一份只干一件事**：用**最小的代码**把板子上那块 2.13 寸墨水屏点亮，
并画一屏「看一眼就知道效果如何」的测试页。

配第 4 篇正文看：**[第4篇-墨水屏点亮与显示实测.md](../第4篇-墨水屏点亮与显示实测.md)**。

> 它**不是**厂家驱动搬过来 —— 厂家的 `smp.c` + `Font.h`（79.8 KB 字模和位图）
> 加上一堆 `DELAY_S(5)`，谁都看不懂哪里能改。这里的驱动把面板"魔法"逐字照抄，
> 剩下的部分自己写，**整个驱动能一屏读完**。

## 二、面板的硬事实（写代码前先记住这几条）

| 项 | 值 |
|---|---|
| 控制器 | **SSD1673**，RAM **250 栅极 × 128 源极** |
| 可视区 | **250 × 122，横屏**（这是屏的**自然方向**，不是旋转出来的） |
| 颜色 | 只有**黑白**两色，灰度靠**抖动**凑 |
| 位约定 | **1 = 白，0 = 黑**（跟直觉相反） |
| 帧缓冲 | `fb[250][16]` = **4000 字节**，`[栅极][源极字节]`，MSB 先出 |
| 引脚 | 软件 SPI：`SCLK=PA5  SDA=PA7  CS=PA4  DC=PB1  RST=PB0  BUSY=PC5` |

> ⚠️ **底板丝印跟驱动对不上**：PA4 标着 `LCD_RESET`、PB0 标着 `LCD_BL` ——
> 那是从早先 TFT 设计抄来的旧名（**墨水屏没有背光**）。**按驱动来，别按丝印来。**
> 详见第 4 篇 §1.3。

**跟 BC28 不冲突**：BC28 走 USART2（PA2/PA3），CH340 走 USART1（PA9/PA10），
跟上面这 6 根脚完全错开 —— 墨水屏和 NB-IoT 可以同时跑。

## 五、实现上必须知道的几个点

1. **"画"和"刷"是分开的。** 所有图元只改帧缓冲（`fb[][]`），**不碰屏**；
   要上屏必须显式调 `EINK_Refresh()`。刷一次要 2.5 秒，先把一屏拼好再一次刷，
   比"边算边刷"快一个数量级。
2. **BUSY 低电平有效**（低 = 空闲，高 = 忙），而且**带超时**：
   屏没插好时 8 秒后返回 0 退出，不会死等。**`EINK_Refresh(&ok)` 里的 `ok` 就是"屏在不在"的答案。**
3. **LUT（`0x32` 那 29 字节）必须逐字节照抄。** 它是驱动波形 ——
   改一个字节最轻是残影加重，最重是整屏不显影。**没有它屏根本不会显影。**
4. **不看 SysTick 中断也能计时。** 读 `SysTick->CTRL` 的 `COUNTFLAG` 计数毫秒
   （每次读会清标志，所以每个 ms 最多计一次）。**不用改 `stm32l1xx_it.c`。**
5. **`TimingDelay_Decrement()` 不能删。** `stm32l1xx_it.c` 的 `SysTick_Handler` 会调它，
   删了链接不过（第 2 篇的透传固件里也踩过同一条）。

## 六、修掉的厂家两个 bug（**都不在墨水屏逻辑里，所以特别难查**）

### 1. RCC 时钟：函数和常量不配套

```c
RCC_APB2PeriphClockCmd(RCC_AHBPeriph_GPIOB, ENABLE);   // 左边写 APB2ENR, 右边是 AHB 的位号
RCC_APB2PeriphClockCmd(RCC_AHBPeriph_GPIOA, ENABLE);
```

| 这一行 | 传进去的值 | 实际打开了 |
|---|---|---|
| `RCC_AHBPeriph_GPIOA` | `0x01` | **SYSCFG**（歪打正着） |
| `RCC_AHBPeriph_GPIOB` | `0x02` | APB2ENR 的**保留位** → **什么都没开** |

**两行都没打开它们声称的 GPIO 时钟。**
在厂家那份工程里看不出来，是因为 GPIOA/B/C 的时钟早被别处正确打开了
（`LED/LED.c:5` 开 GPIOC；`usart/usart.c:61,165` 开 GPIOA/GPIOB）——
**这个 bug 是"哑弹"，只在你换初始化顺序时才响**，而它一响的症状是
「PB0/PB1 不工作 → 屏完全没反应」，看起来像屏坏了。

本驱动**不赌初始化顺序**，自己一次性把 A/B/C 开齐。

### 2. BUSY 被配成**输出**，然后读它 → 假轮询

```c
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_OUT;          // PC5 配成输出 (smp.c:617-620)
#define nBUSY  GPIO_ReadOutputDataBit(GPIOC, GPIO_Pin_5)  // 读的是输出锁存器 (smp.h)
while(1) { if(nBUSY==0) break; }                       // 恒为 0 → 一进去就 break
DELAY_S(2);                                            // 真正在等的是这 2 秒
```

**BUSY 是面板的输出、MCU 的输入。** 读输出锁存器恒得 0，轮询等于没写。
本驱动改成 `GPIO_Mode_IN` + `GPIO_ReadInputDataBit` + 超时。

> 顺带一提：这也解释了「这块板子刷一次要 20 秒」的传言 ——
> 真凶是厂家 `EINK_ShowChar()` 里每个字符两个 `DELAY_S(5)`（**10 秒/字符**）+ `DIS_IMG` 里两个 5 秒。
> **面板本身一次全刷就是 2.5 秒。**
