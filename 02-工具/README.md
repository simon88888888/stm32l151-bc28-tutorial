# STM32L151 + BC28 板子 · 开发工具包

给 STM32L151 + BC28 开发板「编译 → 烧录 → 看串口日志」用的一套脚本。**脚本本身不写死本机路径**
（Keil 装在哪儿、烧写算法 `.FLM` 在哪，都是自动探测的），所以整套可以搬到别的电脑用。

## ⚠️ 如果你是照着教程来、刚下载到这套脚本 —— 只改一行

把整套放进**任意一个英文目录**（比如 `D:\tools\stm32-bc28\`），然后打开
**`flash_and_run.bat` 和 `read_com.bat`，各改第 14 行**：

```bat
if not exist "%PS1%" set "PS1=D:\windows11-tools\stm32-bc28\flash_and_run.ps1"
                               ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 改成你实际放这套脚本的目录
```

这一行是「副本找不到主脚本时的兜底路径」，写的是作者机器上的位置。**不改，双击就会报
`Cannot find flash_and_run.ps1`。** 两个 bat 都要改（`read_com.bat` 里同样的位置）。

改完之后，**只需要把这一个 `flash_and_run.bat` 拷到工程目录下双击**，其余文件都留在原地 ——
bat 找到主脚本后会自动定位工程。（**别把 `.ps1`/`.py` 一起拷过去**：副本会跟这里的正本走散。）

> 另外 `flash_and_run.ps1` 里有一处 `-DefaultProject` 兜底路径指向作者机器的 hello 工程。
> 它只在「当前位置找不到任何工程」时才会用到，此时脚本会明确报 `ABORT: no project found.`
> 并把工程路径传进去的两种写法告诉你 —— **不影响正常使用，可以不管它**。

### 2. 新电脑上要装的东西

| 装什么 | 干什么用的 | 注意 |
|---|---|---|
| **Keil MDK-ARM**（本机是 V5.24a，`C:\Keil_v5`） | 编译 + 烧录 | 必须带 **ARM Compiler 5（AC5）**，本机版本 `V5.06 update 5 (build 528)` |

| **ST-Link 驱动** | SWD 烧录/调试 | Keil MDK 安装时一般会一并装上 |
| **Python 3** | `prep_project.py`（修厂家例程的缺陷）+ `at_console.py`（敲 AT 指令）用 | 两个都是标准库 + 一个 `pyserial`；不用就都不需要 |

> **AC5 是硬门槛。** 这批 2018 年的 ST 标准外设库（SPL）代码用 AC6/ARMCLANG 编不过。
> 老的 MDK（5.24a 这种）自带 AC5；**新的 MDK（5.37 以后）要单独装 AC5 插件**，
> 否则要在 Keil 里 Project → Options → Target → ARM Compiler 里选 `V5.06 update 5`。

### 3. 接线（两根，缺一不可）

| 干什么 | 接哪里 |
|---|---|
| 烧录/调试 | ST-Link 的 **SWDIO / SWCLK / GND** → 板上 **3 针 SWD 口**（**就 3 根线，ST-Link 不给板子供电**） |
| **供电 + 看 log** | 板子**自己的 USB1**（CH340）→ 电脑，**独立的一根 USB 线**（**这根线同时就是板子的电源**） |

**ST-Link 只管信号**（3 根线，没有 VCC）——**只负责下载（load）/调试**，不供电、不出日志。
板子的电**只能来自 USB 或电池**，由那个**黑色拨键**（电源选择，原理图 SW7）选：
**拨到左边 = USB 档**，**拨到右边 = 电池档**（调试期放左边；USB 档**不影响充电**）。

**两个 USB 口**（原理图确认）：**USB1** = CH340G 主口，**供 STM32 电 + 出调试信息**；
**USB2** = FT232/PL 那条，另一个数传口（VBUS 也接在同一条 `VCC_USB` 上）。

所以 **USB1 是一根线干两件事：供电 + 串口**，它没插就是「板子全黑 + 电脑上看不到 COM 口」两个症状同时出现。
「ST-Link 插了、烧录成功、串口一个字没有」最常见的原因就是 **USB1 没插**。

> ⚠️ **别把这两个键搞混：** 黑色拨键（SW7）= 电源选择（**左 = USB 档**，**右 = 电池档**）；
> **`BAT_SHOW` 那个拨动键 = 显示电池电量**，跟 MCU 供电无关。
> 判据：板上那颗**常亮的 POW 灯**（跨在 3.3V 上）**灭 = 3.3V 没起来**。
> 注意**充电灯亮 ≠ 3.3V 有**（充电走 `VCC_USB→FUSE→VUSB→TP5410`，不经过这个开关）。

### 4. 跑起来

```bash
# 把 bat 拷到工程目录下双击，或者：
powershell -NoProfile -ExecutionPolicy Bypass -File "<本目录>\flash_and_run.ps1" "<工程目录或 .uvproj>"
```

不传工程路径时，它会在**当前目录**里找 `Project.uvproj`（先往上找最近的祖先，再往下按
`\MDK-ARM\Project.uvproj` 后缀逐层找，浅的优先）。**找到一个就用；找到多个就列出来让你选，
回车 = 取产物最新的那个**（或加 `-Yes` 直接取最新的）。

> ⚠️ 脚本里有个 `-DefaultProject` 兜底路径指向本机的 hello 工程。**换电脑后如果那个路径不存在，
> 又没在当前目录找到工程，就会报 `ABORT: no project found.`** —— 这时把工程路径传进去即可。

### 5. 看不到 COM 口怎么办（原理图已确认，别再瞎猜）

**关键事实**：CH340G 的 **VCC（16 脚）直接接在 `VCC_USB` 上** —— 就是 USB1 座子的 VBUS，
**在电源选择拨码开关之前**（原理图上厂家自己写着「**CH340只有在USB插上时才有电**」）。
那个拨码开关（**SW7**，电源选择，左 USB / 右 电池）只管 `+5/VCC_5V` 从哪儿来（USB 还是电池升压），**管不到 CH340**。

所以判据是：

| 现象 | 结论 | 怎么办 |
|---|---|---|
| **COM 口一个都没有** | CH340 没上电或没枚举 → **USB1 没插到这台电脑** | 插到**电脑**的 USB 口。**插充电器/充电宝/关掉的 HUB 不算**（那不是 USB 主机，端口不会出现） |
| 同上，换了线也不行 | 线是**只能充电**的线（VBUS 通了、D+/D- 没通）；或线坏；或电脑那个口坏 | 换一根**能传数据**的线、换一个 USB 口 |
| **端口有、但一个字节都没有**，POW 灯灭 | **电源选择开关没拨到位** → 3.3V 没起来，MCU 没跑 | 把 SW7 拨到**左边（USB 档）**并拨到底（充电灯亮不代表 3.3V 有 —— 充电走 FUSE→TP5410，**不经过这个开关**） |
| **端口有、但一个字节都没有**，POW 灯亮 | 不是供电问题 → 程序没在跑，或流控被打开了 | 检查串口工具流控必须是**无**；再重新烧一次 |

> ⚠️ **别把「没有 COM 口」和「板子坏」划等号。** 拨码开关位置**不可能**造成「端口消失」——
> 它影响的是 MCU，不是 CH340。

`read_com.bat` 遇到这种情况会把上面几条直接打在屏幕上，并**等你 20 秒**让你把线插上
（插上就自动接着抓日志，不用重新运行；已实测）。不想等就 `-WaitPort 0`。

## `prep_project.py`：厂家例程为什么编不过/烧不进/烧了不跑

资料包里 13 个例程工程，**每一个的 target 1 都带同样三处缺陷**（target 1 = 本板芯片
`STM32L1XX_MD(STM32L1xxxBxx)` / `STM32L151RC`；target 2/3/4 是别的芯片，不用管）：

| # | 缺陷 | 不修的后果 |
|---|---|---|
| ① | `IncludePath` 缺 `..\..\..\Libraries\CMSIS\Include` | 报 `cannot open source input file "core_cm3.h"`，**编不过** |
| ② | ST-Link 驱动串缺 `-FP0(<FLM 绝对路径>)` | 算法没加载，报 **`Erase Failed!`**（错误信息极具误导性，跟保护/容量无关），**烧不进去** |
| ③ | ST-Link 驱动串是 `-FO7` 而不是 `-FO15` | `-FO15` 才是「Reset and Run」。`-FO7` 会**烧进去但芯片被留在停机状态，串口一个字都没有** |

```bash
python prep_project.py <MDK-ARM 目录或 Project.uvproj> [--check] [--flm <FLM 路径>]
```

- `--check` 只检查不改；不加就修（自动留 `.bak-prep` 备份）
- `--flm` 手工指定烧写算法（自动探测不到时用）
- ③ **每个例程不一样**（例程 3 是 7、例程 12 是 15），所以必须逐个检查，不能照抄
- 判据：烧录日志 `flash.log` 里有没有 **`Application running ...`** 这句

> **想手改 / 想核对自己改对没有**：手册仓库里的 **`03-工程改动/`** 存了这三处缺陷在
> `Project.uvproj` / `Project.uvopt` 里的**改动 diff**（作者本工程那一版），逐条标了对应哪处缺陷、
> 以及想在 Keil 界面里点哪里改。**它是说明书不是补丁**（`-FO` 每个例程不一样、`-FP0` 里是作者机器的
> 绝对路径，patch 不上去），所以还是**优先跑 `prep_project.py`**。

## 其它几个坑（都踩过）

- **`-f` 只下载、不编译。** Keil 命令行烧的是「**上次编译出来的**」那份 `<OutputName>.axf`，
  所以「改了代码没编译就烧 = 烧进去的还是旧程序」，而且不报错。先 `-b` 再 `-f`（脚本默认带编译）。
- **Keil 烧的是工程自己的产物，指定不了别的文件。** 想换程序只能**换工程**或**换 target**。
  烧一个来路不明的裸 `.hex`/`.axf` 要 STM32CubeProgrammer CLI（**本机没装**）。
- **Keil 界面开着时命令行连不上 ST-Link**（报 `Target DLL has been cancelled`），必须单一占用。
- **必须装 `Keil.STM32L1xx_DFP` 器件包**，否则全盘没有任何 STM32L1 的 `.FLM`，下载直接失败。
- `.uvopt` 里的驱动串**会被 Keil 界面覆写**：如果谁在 Options for Target → Utilities → Settings →
  Flash Download 里动过算法列表，上面 ②③ 两个坑都会回来。
